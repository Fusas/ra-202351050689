Antes e depois — o mesmo resultado, duas escritas

Os dois trechos abaixo produzem exatamente a mesma lista de frases: os produtos disponíveis com preço abaixo de R$ 200, formatados para leitura. Nenhuma explicação de sintaxe agora — só uma pergunta: qual dos dois você prefere depurar às 23h da véspera da entrega?

JavaScript de 2010 — 17 linhas 
var resultado = [];

for (var i = 0; i < PRODUTOS.length; i++) {
  var p = PRODUTOS[i];

  if (p.disponivel == true) {
    if (p.preco < 200) {
      var linha = p.nome
                + " - R$ "
                + p.preco.toFixed(2)
                + " ("
                + p.categoria
                + ")";
      resultado.push(linha);
    }
  }
}

console.log(resultado);
JavaScript moderno — 4 linhas 
const resultado = PRODUTOS
  .filter(p => p.disponivel && p.preco < 200)
  .map(p => `${p.nome} - R$ ${p.preco.toFixed(2)} (${p.categoria})`);

console.log(resultado);

Copie os dois no console e confira que a saída é idêntica. Depois compare: quantas variáveis auxiliares cada um cria? Em qual dos dois é possível ler a intenção sem executar mentalmente o código?

Roteiro das 6 rodadas

As perguntas completas estão no seu handout impresso. Aqui fica só a ordem, para você não se perder:

  1. const, let e var — o que cada um impede, e qual deles ignora as chaves { }
  2. Tipos e comparação — typeof, e por que '10' == 10 é verdadeiro
  3. map — transformar a lista preservando o tamanho
  4. filter e find — selecionar: um devolve lista, o outro devolve item
  5. reduce — colapsar a lista em um único valor, pelos dois caminhos
  6. Destructuring e spread — extrair campos, copiar objetos e a armadilha da referência

A regra da fase: escreva a previsão no papel antes de apertar Enter. Previsão errada não é erro — é o momento em que você descobre que a sua ideia sobre a linguagem estava incompleta. Registre-a mesmo assim.
